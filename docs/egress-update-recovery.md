# 更新器失败诊断与有界恢复

2026-09-07 21:32:30的原异常被旧版捕获后丢弃，stderr也未保留，不能追认其为DNS或curl超时。
已证实旧行为是任何异常写UPDATE_FAILED并锁存，进程退出且Restart=no。

新增脱敏字段：失败阶段、异常类型、工具名、退出码；不记录stderr、参数、URL、响应或秘密。
仅observe阶段明确curl传输错误（DNS、连接、超时等）允许退出75，systemd等待15秒重启，300秒内最多3次启动。
每次失败立即撤销内核通行、写不可信状态；不是保留旧绿色状态等待重试。
HTTP错误、解析错误、权限/文件/nft写入错误和未知异常继续锁存，退出1且不自动重启。
错误出口、规则变化、UID或路由检查失败保持原锁存语义。
连续失败超过启动限制仍阻断，需人工检查后重新启动；不存在无限重试。

更新器重新观测成功不解除应用已锁存的阻断，不自动恢复业务。当前用户批准的恢复仅reply-only，
由受控主服务重启重新建立owner；发货、订单恢复仍false，cutoff仍空。
