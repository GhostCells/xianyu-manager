# 闲鱼选品数据观察设计

版本：v1.0  
日期：2026-08-22  
状态：设计完成，尚未开发

## 1. 目标与边界

本阶段的目标是观察每日采集链路是否稳定、取得的数据是否足够完整，以及不同关键词带来的商品样本是否具有持续研究价值，为后续评分公式提供真实基线。

当前模块定位是：

> **采集质量与数据分布观察器，不是评分器，也不是自动选品器。**

本阶段：

- 只读取 `selection_search_runs`、`selection_items` 和 `selection_item_snapshots`。
- 不写入 `selection_scores`。
- 不调用 AI。
- 不产生“值得做”或“不值得做”的自动结论。
- 不把想要数、浏览数、收藏数解释为销量。
- 不修改搜索、详情补采、自动回复或自动发货流程。
- 未采集的指标继续保持 `NULL`，不按 0 参与分布计算。

建议观察周期至少为 14 天；如果关键词每天只有少量详情样本，建议积累 28～30 天后再确定评分阈值。

## 2. 数据口径

### 2.1 时间口径

所有每日统计按 Asia/Shanghai 自然日计算：

```text
当日 00:00:00 ≤ started_at / observed_at < 次日 00:00:00
```

搜索运行以 `selection_search_runs.started_at` 归属日期；商品详情指标以 `selection_item_snapshots.detail_observed_at` 归属日期。若旧记录没有 `detail_observed_at`，观察时可退回使用 `observed_at`，同时标记时间口径为 fallback。

### 2.2 成功状态

- 搜索成功：`selection_search_runs.status = 'success'`。
- 搜索部分成功：`status = 'partial'`，单独统计，不并入严格成功率。
- 详情成功：`selection_item_snapshots.detail_status = 'success'`。
- 详情失败：`failed` 或 `verification_required`。
- 详情未执行：`skipped`，不应混入“详情执行失败”分母。

### 2.3 数值口径

详情页已确认字段：

| 本地字段 | 来源 | 含义 |
|---|---|---|
| `want_count` | `data.itemDO.wantCnt` | 平台展示的商品想要数 |
| `browse_count` | `data.itemDO.browseCnt` | 平台展示的商品浏览数 |
| `collect_count` | `data.itemDO.collectCnt` | 平台展示的商品收藏数 |

这些字段是累计互动指标，不是销量、成交量或利润。

## 3. 每日采集统计指标

### 3.1 搜索关键词数量

同时展示三个口径：

| 指标 | 定义 |
|---|---|
| 计划关键词数 | 当日调度配置中应执行的去重关键词数 |
| 实际执行关键词数 | 当日存在搜索运行记录的去重关键词数 |
| 完成关键词数 | 当日至少有一次 `success` 搜索的去重关键词数 |

仅依赖现有数据库时，可以稳定计算后两项。计划关键词数来自调度配置，需要未来观察模块读取配置快照后才能准确回溯。

### 3.2 搜索成功率

严格成功率：

```text
搜索成功率 = success 运行数 / 已结束运行数
```

其中已结束运行不包括 `pending` 和 `running`，包括：

```text
success + partial + failed + blocked
```

同时单独展示：

- `partial_rate`
- `failed_rate`
- `blocked_rate`
- 各 `error_code` 次数
- 搜索平均耗时（当前表尚无精确耗时字段，可由 `finished_at-started_at` 计算）

不能把 `result_count=0` 直接认定为失败；必须结合运行状态和错误码判断。

### 3.3 商品发现数量

每日建议展示：

| 指标 | 计算方式 |
|---|---|
| 搜索返回商品条数 | 当日成功运行的 `result_count` 合计 |
| 去重发现商品数 | 当日运行关联快照中的去重 `item_id` 数 |
| 首次发现商品数 | `selection_items.first_seen_at` 位于当日的商品数 |
| 重复商品数 | 搜索返回条数减去当日去重商品数 |
| 跨关键词重复数 | 当日命中两个及以上关键词的 `item_id` 数 |
| 单关键词平均发现数 | 去重发现数 / 完成关键词数 |

搜索返回商品条数代表卡片数量，去重商品数代表独立商品数量，两者必须分开显示。

### 3.4 详情成功率

详情执行数：

```text
detail_attempted = success + failed + verification_required
```

详情成功率：

```text
详情成功率 = detail_status='success' / detail_attempted
```

同时展示：

- 成功数
- 失败数
- 验证中止数
- skipped 数
- 各 `detail_error_code` 次数
- 搜索发现到详情成功的覆盖率

```text
详情覆盖率 = 详情成功的去重 item_id / 当日搜索发现的去重 item_id
```

`skipped` 表示没有被选入详情补采，不属于失败。

### 3.5 字段完整率

只在 `detail_status='success'` 的快照中计算字段完整率：

```text
want 完整率    = want_count IS NOT NULL / 详情成功数
browse 完整率  = browse_count IS NOT NULL / 详情成功数
collect 完整率 = collect_count IS NOT NULL / 详情成功数
价格完整率     = price_cents IS NOT NULL AND price_parse_status='parsed' / 搜索快照数
```

三字段联合完整率：

```text
互动字段联合完整率 =
  want_count、browse_count、collect_count 均非 NULL 的快照数
  / 详情成功数
```

还应展示缺失组合，例如：

- 仅缺 `collect_count`
- 仅缺 `browse_count`
- 三项均缺失
- 详情状态成功但字段全部缺失

最后一种情况通常代表解析规则或接口结构异常，应优先排查。

## 4. 商品分布指标

### 4.1 样本选择原则

分布统计默认只使用：

- `detail_status='success'`
- 对应字段非 `NULL`
- 每个商品在统计周期内的最新一条快照

使用“每个商品最新快照”可以避免被多次观察的商品在横截面分布中获得更高权重。趋势分析则保留全部历史快照，另行计算。

每个指标都必须同时展示有效样本数 `n` 和缺失数，样本量不足时不解释分布。

### 4.2 wantCnt 分布

展示：

- 样本数、缺失数、真实 0 数量
- 最小值、最大值
- P25、P50、P75、P90、P95
- 均值（只作辅助）
- 建议直方图区间：`0`、`1–5`、`6–20`、`21–50`、`51–100`、`101–300`、`301+`

想要数通常是偏态长尾数据，判断基线应优先使用中位数和百分位，不使用均值作为主要阈值。

### 4.3 browseCnt 分布

展示：

- 样本数与缺失数
- P25、P50、P75、P90、P95
- 建议直方图区间：`0–99`、`100–499`、`500–999`、`1,000–4,999`、`5,000–9,999`、`10,000+`
- 可增加 `log1p(browse_count)` 分布，用于观察长尾而不改变原始数据

浏览数只反映累计曝光/访问规模，不等于有效需求。

### 4.4 collectCnt 分布

展示方式与 wantCnt 一致：

- 样本数、缺失数、真实 0 数量
- P25、P50、P75、P90、P95
- 建议区间：`0`、`1–5`、`6–20`、`21–50`、`51–100`、`101+`

收藏与想要的产品语义可能重叠，暂时分别观察，不合并成“独立意向人数”。

### 4.5 wantRate 分布

原始想要率：

```text
want_rate = want_count / browse_count
```

计算条件：

- `want_count IS NOT NULL`
- `browse_count IS NOT NULL`
- `browse_count > 0`

为降低小样本波动，同时观察平滑想要率：

```text
smoothed_want_rate = (want_count + 2) / (browse_count + 100)
```

展示：

- 有效样本数
- 因 `browse_count=0` 无法计算的数量
- P25、P50、P75、P90、P95
- 原始率和平滑率的对照
- 按浏览量区间分层后的分布

禁止把想要率称为成交率。

### 4.6 collectRate 分布

原始收藏率：

```text
collect_rate = collect_count / browse_count
```

平滑收藏率：

```text
smoothed_collect_rate = (collect_count + 2) / (browse_count + 100)
```

计算条件和展示方式与 wantRate 相同。收藏率是互动强度参考，不是购买转化率。

### 4.7 分组维度

所有商品分布至少支持以下切片：

- 日期
- 关键词
- 价格区间
- 首次发现日与历史商品
- 搜索排名区间（1–5、6–10、11–20、21+）
- 详情字段是否完整

第一版观察时不建议把不同关键词的数据直接混成一个阈值；应先看同关键词分布，再看全局分布。

## 5. 关键词质量评估

### 5.1 评估原则

关键词质量由“采得到”“采得新”“数据完整”“样本表现稳定”四类信号共同判断，不直接使用单个高互动商品下结论。

关键词观察卡建议包含：

| 维度 | 指标 |
|---|---|
| 可采集性 | 搜索成功率、阻断率、平均结果数 |
| 发现能力 | 日均去重商品数、首次发现率、跨日重复率 |
| 补采质量 | 详情覆盖率、详情成功率、三字段联合完整率 |
| 商品表现 | want/browse/collect 中位数与 P75/P90 |
| 意向强度 | 平滑 wantRate、collectRate 中位数与 P75/P90 |
| 持续性 | 连续有结果天数、连续出现商品比例 |

### 5.2 高潜发现能力

在尚未实现评分前，不定义单一“高潜分数”。建议使用周期内相对阈值观察：

```text
高互动样本：
  want_count 或 collect_count 位于同日同关键词 P75 以上

高意向样本：
  smoothed_want_rate 或 smoothed_collect_rate 位于同日同关键词 P75 以上
  且 browse_count 不低于该关键词 P50
```

关键词高潜发现率：

```text
高潜发现率 = 满足观察条件的商品数 / 有完整详情数据的商品数
```

这只是用于比较关键词的观察指标，不代表商品一定值得制作。

为避免极小样本误导，建议关键词在周期内至少拥有：

- 7 个成功采集日；
- 30 条三字段完整商品样本；
- 每日至少 3 条详情成功样本。

未达到时标记为“样本不足”，不判定优劣。

### 5.3 无效关键词识别

满足以下一种情况时先标记“需复核”，不要直接自动停用：

- 连续 7 天平均搜索结果少于 3 条。
- 连续 7 天首次发现率低于 5%，样本高度重复。
- 详情覆盖充分但三字段联合完整率持续低于 70%。
- 14 天内平滑 wantRate 与 collectRate 的 P75 均显著低于其他关键词。
- 标题样本明显偏离目标业务，但这项目前需要人工抽查。
- 搜索频繁 blocked/failed，导致有效天数不足。

“接口失败、登录阻断、未执行”属于采集问题，不能据此认定关键词无效。

### 5.4 建议的关键词观察状态

```text
collecting       数据积累中
insufficient     样本不足
productive       持续发现较多可观察商品
low_yield        有效产出较低，建议人工复核
collection_issue 采集质量异常，先修链路
paused           人工暂停
```

这些状态仅供观察模块展示，MVP 不自动修改调度配置。

## 6. 为评分系统需要积累的数据

### 6.1 当前必须持续积累

| 数据 | 用途 |
|---|---|
| `run_id`、关键词、运行状态、错误码 | 判断数据缺口来自市场还是采集失败 |
| `item_id`、首次/最近发现时间 | 计算商品存续时间和新发现率 |
| 每次搜索排名 | 观察排名稳定性和变化 |
| 每次价格 | 观察价格变化，建立关键词价格带 |
| `want_count` 历史快照 | 计算新增想要数和增长速度 |
| `browse_count` 历史快照 | 计算新增浏览数和曝光增长 |
| `collect_count` 历史快照 | 计算新增收藏数和增长速度 |
| 详情状态及错误码 | 识别缺失偏差和解析异常 |

### 6.2 至少两次快照才能计算

对于同一 `item_id` 的相邻有效快照：

```text
delta_hours   = 本次观测时间 - 上次观测时间
delta_want    = 本次 want_count - 上次 want_count
delta_browse  = 本次 browse_count - 上次 browse_count
delta_collect = 本次 collect_count - 上次 collect_count
```

标准化到 24 小时：

```text
want_growth_24h    = delta_want / delta_hours × 24
browse_growth_24h  = delta_browse / delta_hours × 24
collect_growth_24h = delta_collect / delta_hours × 24
```

新增浏览意向率：

```text
incremental_want_rate = delta_want / delta_browse
incremental_collect_rate = delta_collect / delta_browse
```

仅当 `delta_browse > 0` 且时间间隔合理时计算。若累计值下降，应标记 `counter_reset_or_source_change`，不能简单当作负增长评分。

### 6.3 后续评分校准需要的人工标签

评分实现前建议增加但本阶段暂不开发的人工反馈：

- `reviewed_at`
- `manual_decision`：关注 / 暂缓 / 不做
- `manual_reason`：需求弱、价格不合适、侵权风险、交付困难、售后重等
- `product_created`：是否最终制作商品
- `listing_published`：是否最终上架

这些标签用于检验未来评分是否真的减少人工工作，不用于反向修改原始采集事实。

### 6.4 暂时缺失但未来有价值的数据

- 可靠发布时间或商品年龄。
- 单品真实销量。
- 评论数量与反馈内容。
- 商品上下架状态。
- 卖家级信息与单品信息的明确区分。
- 自有商品的曝光、咨询、成交和退款数据。

在字段口径未验证前不能填充或推断。尤其不能使用卖家累计销量替代单品销量。

## 7. 建议的日报结构

数据观察日报可以按以下顺序生成，第一版可先输出 Markdown 或日志摘要，不需要前端：

```text
一、采集健康度
  计划/执行/成功关键词数
  搜索成功率与错误分布
  详情成功率与验证中止数
  字段完整率

二、商品发现
  搜索返回条数
  当日去重商品数
  首次发现商品数
  跨关键词重复数

三、互动分布
  want/browse/collect 的 n、P50、P75、P90
  平滑 wantRate/collectRate 的 n、P50、P75、P90

四、关键词对比
  每个关键词的发现数、详情完整数、分布指标
  样本不足、采集异常、低产出标记

五、数据警报
  连续失败
  成功但字段全部缺失
  累计计数异常下降
  样本量骤降
```

日报中的百分比必须同时显示分子、分母，分布必须显示有效样本数，防止小样本产生误导。

## 8. 数据质量告警建议

先设计告警，不在本阶段实现自动通知：

| 条件 | 建议级别 | 含义 |
|---|---|---|
| 当日搜索成功率低于 80% | 高 | 搜索链路可能异常 |
| 出现 `blocked` 或验证中止 | 高 | 需要人工查看登录/验证 |
| 详情成功率低于 80% | 高 | 详情接口或页面状态异常 |
| 详情成功但三字段联合完整率低于 90% | 高 | 解析结构可能变化 |
| 当日商品发现量较近 7 日中位数下降 70% | 中 | 市场变化或采集异常 |
| 某关键词连续 7 天无新商品 | 中 | 关键词可能低产出 |
| 数值计数出现下降 | 中 | 商品状态变化或字段口径异常 |

阈值在前 14 天只用于提示，不用于自动暂停或修改任务。

## 9. 第一阶段输出范围

后续真正开发观察模块时，建议先实现最小只读能力：

1. 指定日期的采集健康摘要。
2. 按关键词分组的商品数和详情完整率。
3. want/browse/collect 与两种平滑率的基础百分位。
4. 最近 7 天每日趋势。
5. 明确列出样本量不足和采集异常。
6. 输出 Markdown/JSON 报告，不开发前端。

暂不实现：

- 自动评分。
- AI 判断。
- 自动停用关键词。
- 自动推荐商品。
- 评论和卖家分析。
- 自动上架或制作商品。

## 10. 结论

数据观察阶段首先要回答两个问题：采集链路是否持续可靠，以及不同关键词是否稳定带来足够、完整、可比较的商品样本。累计互动指标用于描述分布，历史快照用于描述增长，两者都不能被解释为销量。

只有在连续 14～30 天内保持较高搜索成功率、详情成功率和字段完整率，并为主要关键词积累足够的重复快照后，才适合确定评分权重和候选阈值。
