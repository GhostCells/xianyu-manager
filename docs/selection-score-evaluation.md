# 闲鱼选品规则评分效果评估方案

版本：v1.0  
日期：2026-08-23  
适用评分版本：`rule-mvp-v1`  
状态：观察方案，不修改评分公式、不调整权重、不接入 AI

## 1. 评估目标与边界

本阶段需要验证的问题是：

> 在同一关键词、同一搜索批次中，按规则分数优先查看候选，是否比随机查看候选更容易发现“值得测试”、最终“已测试”或“已成交”的商品。

当前规则评分仍然只是候选排序器，不是自动选品器。评估结果不能证明：

- 高分商品一定能成交。
- 浏览量、想要数或收藏数等于销量。
- 某个商品可以直接复制或上架。
- 商品不存在版权、合规、交付或售后风险。

本阶段不修改 `rule-mvp-v1` 的公式和权重。观察期间如发现问题，只记录，不覆盖历史分数。

## 2. 评估前提

进入正式效果评估的批次应满足：

1. 同一 `run_id + keyword` 至少有 5 条完整详情样本。
2. 所有参与比较的商品都有正式 `total_score`。
3. 评分发生在人工审核之前，避免人工结果影响候选排序。
4. 人工审核使用统一状态和基本判断口径。
5. 每次状态变化保留在 `selection_item_reviews`，不能只看商品当前状态。
6. 评估时记录评分版本，不能混合不同版本的分数。

建议先固定运行 `rule-mvp-v1` 至少 14～30 天，再判断是否需要调整。

## 3. 如何评估评分是否有效

### 3.1 基本评估单位

优先使用以下比较单位：

```text
同一个 keyword
+ 同一个 search_run
+ 同一个 score_version
```

这样可以避免不同关键词市场规模、不同采集日期和不同搜索结果数量造成干扰。

### 3.2 评价标签

将人工审核状态转换为不同强度的观察标签，但不回写评分：

| 人工状态 | 观察含义 | 是否作为正向结果 |
|---|---|---:|
| 待审核 | 尚无结论 | 不进入命中率分母 |
| 值得测试 | 人工认为值得进一步验证 | 是，弱正向 |
| 不值得测试 | 人工明确排除 | 否 |
| 已测试 | 已投入实际验证 | 是，中等正向 |
| 已成交 | 已产生真实成交 | 是，强正向 |

“值得测试”只能说明人工认可，不等于市场成功；“已成交”也需要结合测试成本、退款和售后判断质量。

### 3.3 核心对照方法

每个合格批次建立两组：

- 评分组：按总分从高到低取前 K 条。
- 随机基线组：从同一批次剩余候选中随机抽取同样数量。

建议第一版使用：

```text
K = min(5, ceil(完整候选数 × 20%))
```

如果候选样本很少，应只做描述性观察，不下统计结论。

为降低一次随机抽样的偶然性，可以在离线统计中重复随机抽样 100～1000 次，使用随机组指标的平均值和区间作为基线。这个过程不影响商品状态和评分结果。

### 3.4 核心有效性判断

评分初步有效应同时满足：

1. Top-K 的“值得测试及以上”比例高于随机基线。
2. Top-K 的“已测试”比例高于随机基线。
3. Top-K 的“已成交”比例不低于随机基线。
4. 分数从高到低分组后，正向结果比例总体呈下降趋势。
5. 结果在多个关键词和多个采集日中重复出现，而不是由单一批次贡献。

## 4. 高分候选统计指标

### 4.1 Top-K 命中率

```text
Top-K 值得测试命中率 =
Top-K 中最终状态为值得测试/已测试/已成交的数量
÷ Top-K 中已完成人工审核的数量
```

同时计算：

- `Top-3` 命中率
- `Top-5` 命中率
- `Top-10%` 命中率
- `Top-20%` 命中率

待审核商品不应被当成否定结果。

### 4.2 提升倍数 Lift

```text
Lift@K = Top-K 正向结果率 ÷ 随机基线正向结果率
```

解释示例：

- `Lift@5 = 1.0`：与随机选择相当。
- `Lift@5 = 1.5`：前 5 名发现正向候选的效率约为随机选择的 1.5 倍。
- `Lift@5 < 1.0`：当前排序可能没有帮助或存在反向偏差。

当随机基线正向率为 0 时，不计算倍数，改为展示绝对差值。

### 4.3 人工节省量

```text
发现一个正向候选所需查看数 = 人工查看候选数量 ÷ 正向候选数量
```

分别统计：

- 按分数查看时所需查看数。
- 随机查看时所需查看数。
- 每发现一个“已测试”候选所节省的查看数量。

这项指标最贴合当前目标：减少每天人工刷闲鱼的时间。

### 4.4 分数分层表现

按照批次内相对位置分层，而不是跨关键词直接比较绝对分数：

| 分层 | 范围 |
|---|---|
| A | 前 20% |
| B | 20%～40% |
| C | 40%～60% |
| D | 60%～80% |
| E | 后 20% |

每层统计：

- 已审核数量。
- 值得测试及以上数量与比例。
- 不值得测试数量与比例。
- 已测试数量与比例。
- 已成交数量与比例。

若评分有效，A、B 层的正向结果率应总体高于 D、E 层。

## 5. 人工审核结果关联分析

### 5.1 状态关联

按人工状态统计总分及各分项的：

- 样本数。
- 中位数。
- P25、P75。
- 最小值和最大值。

重点比较：

- “值得测试”与“不值得测试”的分数分布是否有明显区别。
- “已测试”是否更集中在高分区域。
- 高分但“不值得测试”的商品为何被否决。
- 低分但“值得测试”的商品具有什么规则尚未覆盖的特征。

### 5.2 排名关联

由于分数只能在同关键词、同批次比较，建议使用批次内排名百分位：

```text
rank_percentile = 候选在本批次的排序位置 ÷ 本批次正式评分数量
```

观察人工正向结果是否更多集中在前 20%、前 40%。不要直接把不同关键词的绝对分数混在一起比较。

### 5.3 审核原因分析

人工标记“不值得测试”时，建议持续使用结构化 `reason_code`，例如：

- 交付成本过高。
- 版权或合规风险。
- 需求不清楚。
- 售后负担大。
- 同质化严重。
- 与当前能力不匹配。
- 价格空间不足。
- 商品并非数字产品。

统计高分候选的主要否决原因，可以判断评分缺失的是市场指标、业务适配还是风险过滤。但本阶段只观察，不立即改权重。

## 6. 已测试后的效果指标

### 6.1 测试转化率

```text
测试转化率 = 已测试数量 ÷ 已审核候选数量
```

分别统计 Top-K、全部候选和随机基线。

“已测试”代表你愿意投入制作或上架验证，主要衡量评分是否减少了前期筛选工作，不代表最终商业成功。

### 6.2 从发现到测试的时间

```text
测试决策时长 = 首次发现时间 → 首次进入“已测试”的时间
```

观察高分候选是否更快进入实际验证。如果高分候选长期未审核，应先解决人工流程覆盖率，不能直接判断评分无效。

### 6.3 测试成本

建议人工记录但暂不纳入当前公式：

- 制作耗时。
- 软件或 API 成本。
- 素材成本。
- 上架耗时。
- 售前沟通量。
- 售后处理量。

高分但测试成本过高的商品，可能不适合当前业务；这属于业务适配问题，不等于互动评分计算错误。

## 7. 已成交后的效果指标

### 7.1 成交命中率

```text
Top-K 成交命中率 = Top-K 中已成交商品数 ÷ Top-K 中已完成测试商品数
```

分母应优先使用“已测试”，避免把从未上架或从未验证的候选当成成交失败。

### 7.2 测试到成交的时间

```text
首单时长 = 首次进入“已测试” → 首次进入“已成交”
```

该指标可以判断高分候选是否更快获得真实市场反馈。

### 7.3 商业质量指标

如果后续数据具备，可另外观察：

- 实际成交单数。
- 实收金额。
- 退款数量和退款率。
- 售前咨询次数。
- 售后耗时。
- 单位制作时间对应的收入。

仅有一次成交不能证明商品稳定有效。评分评估应同时考虑成交质量、退款和人工成本。

## 8. 数据完整性与偏差控制

### 8.1 审核覆盖率

```text
审核覆盖率 = 已有明确人工结论的候选数 ÷ 正式评分候选数
```

覆盖率过低时，高分命中率会受到选择性审核偏差影响。建议除优先审核高分候选外，也固定抽查一部分中低分候选作为对照。

### 8.2 防止结果泄漏

- 评分必须早于人工状态变化。
- 调整规则时必须创建新 `score_version`。
- 不用同一批数据既调权重又证明权重有效。
- 新权重应使用之后采集的时间段验证。

### 8.3 关键词偏差

按关键词分别统计效果。某个关键词表现好，不能证明规则对全部关键词有效。

至少展示：

- 关键词批次数。
- 正式评分候选数。
- 审核覆盖率。
- Top-K 命中率。
- 随机基线命中率。
- Lift。

### 8.4 小样本处理

- 单批次少于 5 条完整样本：没有正式分数，不进入评分效果统计。
- 单关键词正向审核少于 10 条：只展示描述性结果。
- 观察期过短或成交数极少：不调整权重。
- 比率必须同时展示分子和分母，避免“100%”掩盖只有 1 条样本。

## 9. 后续调整评分权重的依据

只有满足以下条件后才讨论调整权重：

1. `rule-mvp-v1` 已连续运行至少 14～30 天。
2. 有足够多正式评分批次，而不是只有几个商品。
3. 人工审核覆盖高分和随机对照样本。
4. 至少积累一定数量的“已测试”，最好已有多条“已成交”。
5. 某个问题在多个关键词和多个日期重复出现。

### 9.1 可支持调整的证据

- 某分项与“值得测试/已测试”长期无关联。
- 某分项在高分否决样本中持续造成误判。
- 低分正向候选反复显示某项权重不足。
- Top-K 命中率长期不高于随机基线。
- 某价格区间的实际测试与成交结果持续优于当前价格假设。

### 9.2 不足以调整的证据

- 单个商品判断错误。
- 单个关键词一天的数据。
- 只有想要数或浏览数很高。
- 一次成交或一次退款。
- 为了让历史样本看起来更符合预期而反复试权重。

### 9.3 调整后的验证方式

未来如果调整公式：

1. 保留 `rule-mvp-v1` 历史记录。
2. 新建评分版本，例如 `rule-mvp-v2`。
3. 明确记录修改原因和预期改善指标。
4. 在后续新数据上比较 v1、v2 与随机基线。
5. 只有新版本持续改善人工筛选效率，才考虑替换默认版本。

## 10. 建议观察日报结构

每周或每 14 天汇总一次：

```text
评分版本：rule-mvp-v1
观察日期范围：YYYY-MM-DD ～ YYYY-MM-DD

一、数据覆盖
- 正式评分批次
- 正式评分候选
- 已审核候选
- 审核覆盖率

二、高分效果
- Top-3 / Top-5 / Top-20% 正向命中率
- 随机基线命中率
- Lift
- 每发现一个正向候选所需查看数

三、人工反馈
- 值得测试 / 不值得测试 / 已测试 / 已成交数量
- 各状态分数分布
- 高分否决原因
- 低分正向案例

四、实际测试
- 测试转化率
- 平均测试决策时长
- 测试成本与主要阻力

五、成交观察
- 已成交商品数
- Top-K 成交命中率
- 首单时长
- 退款和售后情况（如有）

六、结论
- 是否初步优于随机基线
- 当前证据是否充足
- 继续固定观察或进入新版本实验
```

## 11. 阶段性成功标准

第一阶段可以认为评分“初步有帮助”，建议至少看到：

- 连续多个观察周期中，Top-K 正向命中率高于随机基线。
- `Lift@K` 大多数周期大于 1。
- 按分数查看时，发现一个“值得测试”候选所需查看数下降。
- 高分候选进入“已测试”的比例高于全量和随机候选。
- 没有明显集中在某一个关键词才有效。

如果结果没有优于随机基线，也不应立即自动调权重。应先排查：

- 详情字段完整率是否足够。
- 人工审核覆盖率是否足够。
- 高分候选是否真的被优先审核。
- 人工审核标准是否一致。
- 标题数据是否混入过长描述或无关信息。
- 样本时间是否足够长。

本方案最终要验证的不是分数看起来是否合理，而是：

> 在相同人工时间下，规则排序能否稳定地比随机浏览发现更多值得测试和最终产生有效结果的候选商品。
