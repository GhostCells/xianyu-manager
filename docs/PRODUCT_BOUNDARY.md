# 产品边界（MVP）

## 已确认

- Windows 本地运行，只管理用户在七月份创建的唯一闲鱼账号，网页不提供账号切换；
- 商品库是完整资产库；只有明确加入七月账号的商品才进入日常管理和自动发货；
- 商品制作仍由 Codex 按根目录 `SKILL.md` 与 `发品规范/` 完成；
- 系统只读取 `商品库/`，不把管理数据写入商品目录；
- 一个闲鱼商品只对应一个交付 ZIP 和一个百度网盘分享链接；
- 百度网盘由官方客户端自动备份，首次分享链接由用户手工创建；
- 上架前由系统给出建议，用户确认后才允许一键上架；
- 自动发货只在订单明确进入“买家已付款”后执行；
- 双人小刀只接受平台系统卡片作为状态证据；“待刀成”阶段只免拼，“成功小刀，待发货”阶段才发送交付内容；
- 发货成功后才确认闲鱼发货，并使用订单号保证幂等；
- 监听器明确区分订单系统事件、普通聊天和卖家自身消息；普通聊天只有在用户主动启用 AI 自动回复后才处理；
- 无法唯一匹配订单号、商品 ID、买家、会话或商品链接时停止发送；
- 消息发送确认不明确时进入人工核对，不自动重发；消息已发送但平台确认失败时只补确认；
- 自动回复 API Key 使用 Windows DPAPI 加密，不保存明文 Key 或 Cookie，登录只允许扫码；
- 自动回复仅处理唯一匹配商品的售前文本；敏感话题、模型异常、消息确认不明确或卖家人工发言时停止自动发送；
- 真实账号会话由独立 Edge 用户目录保存并使用 Windows 当前用户保护；SQLite 只记录绑定状态与检查时间；
- 扫码后必须由用户在浏览器内核对账号并点击确认，检测到登录不等于自动确认绑定；
- 当前账号模板中的分类、所在地、成色、发货方式暂按固定值管理；
- 旧账号档案与历史订单只保留作审计并归档，不显示、不登录、不监听、不能重新激活；
- 旧账号发过的商品只保留在商品库作选品排重，不进入七月账号的日常管理页；
- 商品编号保持全局连续，不因账号边界调整而重置；
- 七月账号商品仍完整执行根目录 `SKILL.md` 和 `发品规范/`，不降低制作、交付、五图或质检标准。

## MVP 流程

1. Codex 将通过质检的商品放入 `商品库/NN-商品名/`；
2. 管理系统扫描并运行结构质检；
3. 百度网盘客户端把同一商品目录备份到云端；
4. 用户为交付 ZIP 创建一次分享链接并录入系统；
5. 用户把商品加入当前账号；系统建议价格，用户确认文案、五图、价格与账号模板；
6. 用户点击一键上架，系统填表并提交；
7. 系统记录闲鱼商品链接，建立“一商品—一 ZIP—一分享链接”绑定；
8. 订单进入“买家已付款”后发送链接和提取码；
9. 消息发送成功后确认发货，失败进入人工处理队列。

## 暂不进入 MVP

- 多账号同时在线、跨账号并发操作和团队权限；
- 图片、语音和系统卡片的 AI 自动理解；
- 无人确认的批量上架或定时上架；
- 依赖明文 Cookie 的登录方式；
- 绕过百度网盘官方授权或模拟登录生成分享链接；
- 云服务器长期登录闲鱼账号。
- 绕过闲鱼滑块、扫码、风控或其他人工验证。
