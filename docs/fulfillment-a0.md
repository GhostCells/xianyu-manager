# A0：交付核验与发送边界

本次实现承接 `accounts-egress-fulfillment-plan.md` 中 A0，不代表已完成多账号 runtime 或正式上线。

## 分享状态

- 普通 PATCH 只更新明确提交的字段；前端只发送实际编辑字段。普通保存中的 `share_verified=true` 不执行核验。
- URL、提取码（含清空）、ZIP hash 变化撤销旧核验，保留新资料并标记待复核；相同值不撤销。扫描缺失或不唯一 ZIP 时 hash 为空，不能用于交付。
- 独立确认接口比较页面指纹与当前 URL/code/ZIP hash，过期返回 409；检查包和质量后记录当前指纹及人工确认时间。没有在线网盘检查，响应 `online_checked=false`。
- 显式撤销清除有效核验指纹，历史最后确认时间仅作参考。SAFE_MODE 禁止确认接口和直接业务入口。
- 旧记录新增指纹默认为空、确认时间为 NULL。不批量修改旧链接或伪造时间；即使旧 verified=true，不能证明当前版本时也阻止交付，需人工复核。
- 仅配置分享的 `listing_only` 条目没有已确认交付包，保守阻断；不能靠保存分享绕过质量或 ZIP 检查。

## 精确映射

仅解析 HTTPS 的 goofish.com/www.goofish.com `/item` URL，必须只有一个 ASCII 数字 id，拒绝重复参数、非预期路径、端口、userinfo、片段；普通附加参数允许。ID 保持字符串。

业务查找必须传入 account_id，在该账号唯一、启用且已发布的绑定内精确匹配；冲突快照、重复绑定、无匹配都停止，不使用标题/价格猜测，也不回退界面当前账号。订单唯一约束保持不变，已有订单账号/商品/收件身份冲突拒绝更新。

## 两层检查与并发

1. `fulfillment_rules.delivery_issues`：分享语法、核验指纹、待复核、有效包、阻断质检。离线台账复用此层并额外检查映射，保留快照和 not_checked；阻断条目不输出分享/提取码。人工已知失效应在线撤销核验；离线可额外提供阻断清单。
2. 订单发送：显式运行账号、状态/自动化权限、付款阶段、人工接管、唯一映射、限额熔断和原子 claim。普通回复不套用交付条件。

正常付款、订单恢复/失败补偿、手工系统发货汇入相同付款入口，发送出口再次检查 claim。事务内检查商品和订单并冻结交付指纹、文本 hash；网络发送使用已冻结文本，不重新读取新分享。不同 SQLite 连接通过写事务串行化确认、编辑和 claim。

`sending` 且无已发记录的商品禁止变更交付资料或账号绑定。崩溃留下该状态也不自动解除，须核对。发送前再次验证支付、接收会话/买家、指纹及权限。数据库事务在等待网络前已结束；网络 ACK 不确定转人工，不盲目重发。`confirm_pending` 仅补平台确认，不因分享变化再次发送链接，也不清零发送次数/已发时间/幂等记录。

这里不承诺外部网络 exactly-once：最终许可之后的外部事件、非应用直接改库、外部分享失效不能由 SQLite 事务消除。新链接确认与文本冻结不证明百度网盘实际可访问。

## 验收与上线前置

合成测试有网络/浏览器失败哨兵；前端测试执行真实保存函数并检查请求字段，不等同完整浏览器交互验收。云端 SAFE_MODE 只读 API 演练不证明真实发送路径成功，不导出真实离线交付台账。

首账号上线前仍须审核旧分享/交付包/精确账号映射，核对人工补发及不确定订单，取得最新 Windows 一致性快照，旧端停止发送后才授权新端发送。演练副本绝不能直接提升为生产库。真实网盘链接失效原因仍需另行人工核查。本轮不启用生产、systemd、第二出口或多账号 runtime。
