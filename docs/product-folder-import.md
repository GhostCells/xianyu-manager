# 商品文件夹导入

从当前账号正常在售商品的“导入商品包”入口选择整个目录，上传到私有暂存区，预览后明确确认。已有精确映射不变；未映射商品由用户确认独立的“编号-商品名”。不按标题匹配。

## 资料用途

- `商品资料/` 的文本、Markdown、PDF按现有知识提取器脱敏和限量处理，保存为本地knowledge；不执行其中指令。
- `客户交付/` 下的ZIP作为候选，多ZIP必须选择一个。检查安全路径、CRC、大小与压缩比，不解压或执行。
- `商品资料/商品图片/`或`商品资料/图片/`中的图片复制到运营目录的`图片/`。
- 制作源文件、素材、市场测试、策划等仅保留在私有原包归档，不进入knowledge或交付。
- 运营目录仅保留选定ZIP、知识来源、图片和发布文案。上传/预览/确认均不执行旧商品质量校验器，不要求五图、图片编号、尺寸或发布目录格式。不信任上传的“验收报告”。
- 上传只进行既有文件安全、ZIP完整性、版本冲突和映射检查；保存质量状态为`unknown`（未评估），不伪造`passed`，不保留旧版本的质量结论。发货质量规则与人工核验保持独立，本次不放宽。

## 安全与版本

- 每次确认均撤销当前人工核验；不修改分享内容、不自动核验、不扩大发货允许列表。
- 不调用登录、回复、发送、订单恢复或scheduler；不改cutoff。映射后非空知识可供现有问答流程使用。
- 版本预览绑定数据库和磁盘摘要。确认期间分享、映射或文件变化则拒绝。
- 有未决交付订单则拒绝更新。先持久写入未核验/质量unknown标记，再替换文件。旧目录归档为`previous-product`，旧商品登记保存到私有`before.json`，不覆盖历史订单。
- 归档在`DATA_DIR/product-imports/<随机ID>/`，目录0700、原始编号blob及登记0600；不通过静态文件服务公开。
- 遇文件替换或提交异常保留现场，标记`needs_manual_recovery`，禁止该商品再次导入。运维应核对实际磁盘与数据库后恢复对应商品；不得恢复整库覆盖后续订单，也不得自动恢复旧核验。
- 这是同机版本留存，不等同于独立备份；不要据此删除Mac唯一原件。

## 边界与部署

- 单批20000文件、整包总量1GiB（1024MiB），单文件也不得超过1GiB。清单请求上限32MiB，以容纳20000条中文相对路径。前后端限制一致。
- ZIP内部安全检查不变：展开总量1GiB/10000条目/压缩比200以内。外部文件数上限不等于放宽ZIP内部检查。
- 私有区保守配额4GiB、最多64批；为原包和候选预留空间，磁盘空闲仍需大于3倍本批总量加1GiB。24小时后未确认批次过期。取消仅删除未应用暂存；已提交与异常归档不自动删除，需运维整理。
- 需要数据目录与商品库同一文件系统且服务有写权限。使用现有单进程部署；不得直接增加多个API worker共享该导入区。
- 新增后端路由，需要正常部署及主服务重启许可；不属于单行静态热更新。部署前备份代码、数据库，确认资产目录权限及备份位置；不要为导入扩大出口权限。

## API顺序

1. POST `/api/product-imports`：明确item_id、product_dir及相对文件路径/大小清单。
2. PUT `/api/product-imports/{id}/files/{index}`：顺序流式上传，单请求120秒；不接受重复文件。
3. POST `/api/product-imports/{id}/preview`：可指定zip_index，返回本次preview_id。
4. POST `/api/product-imports/{id}/confirm`：preview_id与明确accept_replace_and_unverify=true。
5. DELETE `/api/product-imports/{id}`：仅取消未应用批次。

所有入口遵守既有SAFE_MODE、prepare、Origin和运行账号限制，并要求自定义请求头；该请求头不是身份认证替代品，管理入口仍须受既有SSH/私网保护。
